# Site v3 review (sitereview, 5 Nov 2026)

Checked with headless Chromium in dark and light at 1440×900, 1366×768, 1280×720, 1024×768, 768×1024, 390×844, 360×740 and 844×390 (landscape phone), plus reduced motion, keyboard use, the ⌘K palette, the copy button, the hero clicks and the docs. Screenshots are in `.devdata/sitereview/` (`home-*` and `docs-*` give the fold and the full page for each size; `el-*` are section crops; `phone-*` are phone details).

Overall: v3 does what the owner asked. It is one idea, has a clear button and looks bespoke. No page scrolls sideways at any size, there are no console errors, the page is light (images are lazy and weigh 7 to 100 KB each), and the download button and Other builds sit above the fold at 1280×720 and 1366×768. Most issues below are about the proof screenshot, the download flow and phones.

## P1: broken or clearly wrong

1. **Every download, GitHub, Releases and issues link is a 404.** `https://github.com/robberttorfs/hangar-oss` doesn't exist yet (checked: 404). This is a known item in `docs/build/STATUS.md` ("Needs the owner" 2). It is still the one thing that makes the site fail its main job, so it has to happen before deploy. Fix: create the repo and a first release, then set `owner`/`repo` in `site/config.mjs`. Then click every `{{dl.*}}` link once on the live site. Shot: none (network).
2. **The Windows file names may not exist (please verify).** `package.json` builds one NSIS target with `arch: ["x64","arm64"]`. With several arches in one NSIS target, electron-builder usually makes one combined installer, so `Hangar-windows-x64-setup.exe` and `Hangar-windows-arm64-setup.exe` may never be produced. STATUS.md already says "check the Windows installer file names". Fix: run `npm run dist:win` (or the CI release) and match `config.mjs` `artifacts.win`/`winArm` to the real file names. If only one combined installer exists, drop the "Windows on ARM" rows (hero builds line, download list, both palettes, docs Install). Shot: `el-download-dark-1440.png`.

## P2: noticeably worse than it should be

1. **The proof screenshot doesn't prove anything (section "The real claude").** All four tiles show the same fresh Claude Code welcome screen ("Try 'fix typecheck errors'"). The tile marked *Needs you* asks nothing; the docs FAQ even explains that case as a confusing one. "api-server" says *Working 1s Thinking* over an empty prompt. Each tile also prints `E:\AI\Claude\hangar-open-source\.devdata\site-demo\…`, which is the owner's own drive layout and reads as a test rig. The phone crop (`wall-tile-*.webp`) has the same problem, and it is the first real image phone users see.
   - Fix: retake `wall-*` and `wall-tile-*` with `tools/site-shots.sh` from demo sessions that have one or two lines of real exchange each. web-app should show a permission prompt, like the overview shot already does. Use a neutral folder such as `~/code/web-app`, so the path line reads `~/code/web-app` or is cropped off.
   - The spotlight box (`.lit`) must still line up after the retake.
   - Shots: `el-feat1-dark-1440.png`, `el-feat1-light-1440.png`, `phone-pan1-dark-390.png`.
2. **The hero never says "Mac and Windows app".** On Windows the button says it. On a phone, on Linux or on an unknown OS it just says "Download", and the only hint is the Other builds list. Five-second test: "what is it" is clear (sessions on one screen), but "is it an app, a CLI or a web thing?" isn't. Fix: change the meta line to `Free and open source, for Mac and Windows. Needs Claude Code.` That is one edit in `index.html` `.meta`. Shots: `home-dark-390x844-fold.png`, `home-dark-1440x900-fold.png`.
3. **The detected-OS download skips the first-launch steps.** On Mac or Windows the hero button links straight to the file, so people never see the `xattr` / SmartScreen steps. The builds are unsigned, so their first launch is a "damaged" or "unrecognised" warning. Fix: in `site.js`, on click of `[data-dl-auto]` with a real file href, let the download go and then scroll to `#download` with `setTimeout(() => location.hash = '#download', 300)`. Better still, add `id="first-mac"` / `id="first-win"` on the two `.first > div` blocks and scroll to the one for this OS. Shot: `home-dark-1440x900-fold.png`.
4. **Intel Macs get the Apple-silicon DMG.** `navigator.platform` is `MacIntel` on every Mac, so the button always gives `arm64`, and on an Intel Mac that won't open. Fix: in `site.js`, read the WebGL `UNMASKED_RENDERER_WEBGL` (it contains "Apple M" / "Apple GPU" on Apple silicon and "Intel" on Intel), and on Intel pick `dl.macIntel` with the label "Download for Mac (Intel)". If it can't tell, keep arm. Shot: none (logic).
5. **On a landscape phone (844×390) the headline fills the screen.** The download button is cut off at the bottom edge (button bottom 396 px in a 390 px view) and no tile is visible. Fix: add `@media (max-height: 500px) and (orientation: landscape) { h1 { font-size: 40px; margin-bottom: 12px } .hero .lede { font-size: 17px; margin-bottom: 16px } }`. Also hide `.ib.key` on touch devices (`@media (hover: none)`), since a ⌘K key is useless there. Shot: `home-dark-844x390-fold.png`.
6. **The phone screenshot crops look clipped, not pannable.** DESIGN.md says the frame "pans sideways on its own", but there's no auto-pan code. The crops just stop mid-word ("move the", "packa", the dev path), with no sign that they scroll. Fix: either add the slow one-time auto-pan the design describes (CSS `scroll-behavior` plus a JS `scrollTo` once in view, skipped under reduced motion), or add a right-edge fade (`mask-image: linear-gradient(to right, #000 85%, transparent)`) that goes away when scrolled to the end. Retaking the overview phone crop so the preview's right edge is in frame would also help. Shots: `phone-pan1-dark-390.png`, `phone-pan2-dark-390.png`.
7. **The docs shortcut table doesn't fit on phones.** At 390 px the Windows column is cut in the middle of the keys ("Ctrl+Shif") and the table needs a sideways scroll with no hint. Fix: under 600 px, show the key for this OS only. `palette.js` already knows `isMac`, so it can set `data-os` on `<html>`, and CSS can then hide the other column (`html[data-os=mac] .doc td:nth-child(3), … th:nth-child(3) { display:none }`). Shot: `phone-docs-table-dark-390.png`.
8. **The og:image is relative and WebP.** `<meta property="og:image" content="/shots/wall-dark-1400.webp">` is on both pages. Most link previews (X, Slack, Discord, iMessage) need an absolute URL, and several don't render WebP. Fix: export a 1200×630 PNG of the hero wall or the screenshot to `public/og.png`, use an absolute URL (add `site` to `config.mjs`), and add `twitter:card=summary_large_image`. Shot: none.

## P3: polish

1. **The detected OS row in the download list isn't marked.** `site.js` sets `data-here` on `#os-mac`/`#os-win`, but no CSS uses it. Fix: `.files li[data-here] .os::after { content: "  ← this computer"; … }` in muted text, or just draw a heavier left border in `--text` (not amber). Shot: `el-download-dark-1440.png`.
2. **The download rows don't look clickable.** They are big headings with a muted filename and no icon. Fix: add the same download glyph as the hero button at the right, beside the filename, in `--muted`. Shot: `el-download-dark-1440.png`.
3. **Phone download rows wrap unevenly.** "Mac, Intel" keeps its filename on the same line while the others wrap below. Fix: under 760 px, make `.files a` `flex-direction: column; align-items: flex-start`. Shot: `phone-download-dark-390.png`.
4. **The hero builds line repeats the detected OS.** "Windows" sits under "Download for Windows". Fix: hide the link that matches the button (`site.js` already knows the OS), or leave it if the owner prefers the full list.
5. **On phones, Other builds pushes the wall below the fold.** You can't use a desktop build on a phone, and "Download" already scrolls to the full list. Fix: hide `.builds` links under 760 px and keep only "Source", or the whole line. That way the wall's top half shows at 390×844. Shot: `home-dark-390x844-fold.png`.
6. **Dimmed hero tiles almost vanish in light mode** (muted at 0.45 opacity, about 1.6:1). It's decorative, but "api / web / notes" vanish, so the wall reads as empty boxes. Fix: in light mode, dim to `.6` instead of `.45`. The amber glow also smears a beige haze over white neighbours in light mode, so lower `--glow` alpha to about `.25` in light only. Shot: `home-light-768x1024-fold.png`, `home-light-1280x720-fold.png`.
7. **Reduced motion: after you click the waiting tile, the wall stays empty for good.** No timer runs, so nothing waits again. Fix: in `hero.js`, when `still` is set, call `ask()` again after `answer()` on a click, or ignore clicks. Shot: `reduced-motion-1280.png`.
8. **DESIGN.md says "hover or tap" settles the waiting tile; only click and tap do.** Either add `mouseenter` on `.tile.hot` or change the doc. Low priority.
9. **The palette's jump returns focus to the old spot.** Pick "First launch steps" and the page scrolls to `#download`, but the dialog's `close` handler puts focus back on the element you were on before, so the next Tab jumps back up. Fix: in `run()`, set `back = target` (give `#download` `tabindex="-1"`) before `close()`.
10. **Palette rows ignore the detected OS.** On Windows the first row is still "Download for Mac, Apple silicon". Fix: move this computer's row to the top on open. Shot: `palette-open-dark-1440.png`.
11. **The two palettes don't match.** Docs says "Download for Windows x64" while the landing page says "Download for Windows". The docs template's first row is also indented oddly. Make them the same.
12. **The palette screenshot (`palette-*-tight*.webp`) is cut at the bottom.** The Overview row touches the frame edge and the palette's bottom border is missing. Fix: recrop it with the same padding as the top. Shot: `el-feat3-dark-1440.png`.
13. **Two different K shortcuts sit on one page.** The nav shows `Ctrl K` (the site palette) while "One key for everything" shows `Ctrl+Shift+K` (the app). That's fine on Mac (⌘K both) but confusing on Windows. Fix: make the site palette also answer Ctrl+Shift+K on Windows and show that in the nav, or drop the text from the nav key and keep only the icon or tooltip.
14. **The landing FAQ names things the page never introduces.** "the overseer" and "a time budget" appear in "Does it cost tokens?". Fix: "Not on its own. A mode is sent once when it starts (and again after a compaction). Only the extras you start yourself, like the side-panel assistant, use tokens."
15. **Copy that reads as filler or slogan:**
    - "Review and Plan **really** block file edits" is on the landing page and in the README. Use "Review and Plan block file edits through a hook; Careful blocks risky commands like push and deploy."
    - "Your settings stay yours." is close to an aphorism. "Your settings aren't touched." is plainer; owner's call.
    - "One key for everything." is fine but sloganish; keep it unless the owner flags it.
16. **The docs overstate the overseer model.** The docs say "It runs Sonnet". Sonnet is the default, but `overseerModel` can be haiku, sonnet or opus in settings (`src/main/main.js:51`, `renderer/app.js:1290`). Fix: "It runs Sonnet by default…".
17. **Two docs lines disagree about where the full shortcut list is.** The docs say "The full list is in the app under Keyboard shortcuts in the palette." The README says "Help → Keyboard shortcuts, or type `?` in the palette." Use the README line.
18. **The gaps between sections are large on desktop** (120 to 220 px, and the page is 6,400 px for five ideas). It's calm, but from Modes to Download feels like empty scrolling at 1440. Fix: drop `.promises`/`.download` `padding-top` to `clamp(110px, 13vw, 170px)`. Keep `.feat` as is.
19. **An orphan at 1024.** The meta line wraps to put "Code." alone on a line. Fix: `text-wrap: pretty` on `.meta` (or a `&nbsp;` in "Claude&nbsp;Code"). Shot: `home-dark-1024x768-fold.png`.
20. **iPad gets "Download for Mac".** iPadOS Safari reports a Mac UA and platform. Fix: treat `navigator.maxTouchPoints > 1` together with Mac as mobile in `site.js`.
21. **The copy button has no screen-reader feedback.** Add `aria-live="polite"` to the button, or a hidden status, so "Copied" is announced. The copy itself works (checked: clipboard holds `xattr -cr "/Applications/Hangar OSS.app"`).
22. **Dead code in palette.js.** The `answer` action, `data-when="waiting"` and the `wall.waiting()` / `answerFirst` calls refer to nothing the wall exposes. Remove them so nobody wires a row to them.

## Keep: what works (don't undo)

- **The hero.** The headline names the thing and the wall explains it with no terminal text. One tile is amber with "needs you" and the rest dim. Your tile never moves (`.c1` is fixed), and the timing is calm: about 4 s waiting, then 3 s at rest. Clicking the waiting tile settles it, it stops off screen and in hidden tabs, and the first frame already shows a waiting tile.
- **Amber is the only signal, and it means one thing.** It's never on a button. The download button is ink on the page colour, which looks confident and bespoke. Petrol neutrals, one background and no section blocks.
- **Schibsted Grotesk at 800 with tight tracking.** It gives the "bold but professional" look, and the mono appears only for tile names, keys and filenames.
- **One idea per section.** Each section has one headline, two lines and one image. No icon grids, pill badges, numbered labels, gradients or glass, and no testimonials. Nothing reads as AI-made.
- **The above-the-fold rule holds.** The button and Other builds are visible at 1280×720, 1366×768 and 1440×900, thanks to the vh-scaled headline and wall.
- **The download section.** It has every build, the filenames, plain first-launch steps and a working Copy button. The FAQ is short and in plain developer voice.
- **The overview shot and the modes menu shot.** They are readable and real, and they show the actual mechanism (number keys, token dots).
- **Docs.** Sticky contents on desktop, folded contents on phones and a 720 px reading column. The facts match the README and the app (modes list, guards, update behaviour, privacy).
- **The ⌘K palette.** Small and fast, it filters with aliases ("xattr", "smartscreen"), handles Esc and arrow keys, and shows "Nothing matches."
- **Basics.** No horizontal scroll at any size, 44 px touch targets in the nav, builds and footer, visible focus rings, a skip link, a reduced-motion still frame, no console errors and a light page.
